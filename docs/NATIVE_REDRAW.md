# 0.2.1 原生窗口重绘修复

0.2.0 的 `render()` 会销毁全部子窗口，随后逐个创建；`layout()` 又使用立即重绘的 `MoveWindow()`。收藏、随机音色、选择参数、切换页面都会走这条路径。中间空白会显示到屏幕，输入框也因被重建而丢失光标和滚动位置。

0.2.1 按原有控件 ID、类名与样式复用 HWND；只创建新增控件、删除离开当前页面的控件。文本相同就不调用 `SetWindowText`，下拉框和列表内容相同就不清空重填。控件更新时暂停重绘，布局通过 `BeginDeferWindowPos` 一次提交，完成后统一恢复绘制；主窗口使用 `WS_EX_COMPOSITED` 合成子窗口绘制。重复点击当前标签直接返回，接口启停只更新按钮和状态文字。

同一组 57 次操作涵盖当前标签、页面切换、收藏、随机音色、调音方案、重置、系统与本地音色切换、扫描和接口启停。旧版累计重建 2370 个在操作前后都存在的控件，新版为 0；台词选区、滚动位置、调音命名和宿主输入的保留检查全部通过。还验证了复用控件从禁用恢复到启用。

通过屏幕截图采样持续检查不应变化的顶部区域：旧版 182 帧中最低内容覆盖率约 65.5%，新版 86 帧中最低为 100%。采样用于复现和比较本机该组操作，不能覆盖两帧间的所有瞬间；控件生命周期检查同时验证了导致闪烁的结构问题已经消除。正常窗口和紧凑窗口均已留图。

复查命令：`python tools/check_native_redraw.py --exe AgentVoice.exe`。对照和当前结果分别见 `native-redraw-baseline.json` 与 `native-redraw-verification.json`。测试使用独立配置目录，并核对真实用户配置及宿主设置的散列值。
