# 0.4.1 · Kokoro 中文声音

本版把默认离线引擎从 AISHELL3 VITS 换成 **Kokoro-82M v1.1-zh INT8**。这是模型替换，不是对旧声音继续加均衡或移调。Kokoro 中文版于 2025-02-26 发布，使用 StyleTTS2 / ISTFTNet 路线，加入专业中文语音数据，原生输出 24 kHz。旧模型原生只有 8 kHz。

## 先试听

打开「声音预设 → 精选声音」，六个入口分别是晓禾 zf_001、云舟 zm_010、晴音 zf_007、远川 zm_041、知夏 zf_032、若晴 zf_017。中文名是应用昵称，编号是模型原始标识；前两种也是模型卡展示的中文样例。六个入口不是官方质量排名，也不代表已经经过真人听感评测。

点击「试听」只播放样句，不改变当前声音；「使用这个声音」应用原速原调、保留模型停顿的参数。名称、音量、台词、启用状态和宿主绑定都保留。满意后保存。「音色与台词」里可以试听自己的第一句台词，也能访问完整声音库：100 种中文声音（55 女、45 男），另有 3 种英文声音，所有声音共用一个模型。

语调由声音、文本和标点生成，模型没有本应用可调用的“开心/撒娇”等情绪指令接口。短句可以写成自然口语，例如「好啦，任务完成了，来看看结果吧。」或「需要你确认一下，我们再继续。」已有台词不会自动改写。

## 默认保留声音本身

默认语速 0、音高 0、停顿 100%、三段均衡 0、压缩 15，自动响度补偿开启。它保留模型的主要动态和语调，不用大幅移调制造声音差异。增益、均衡、压缩、音量、语速、音高和停顿仍可调整，峰值限制为 -1 dBFS。保留七项后期调音预设和 JSON 导入导出；「自然原调」是推荐起点。

旧 VITS 的 noise_scale / noise_scale_w 在 Kokoro 中没有对应控制，界面移除了音色变化、节奏变化两项。旧 JSON 字段仅为兼容保留，不能改变此模型的情绪或随机性。修改后期参数和切换说话人不会重新载入模型。

Kokoro 有中英混合前端，英语单词交给英文词典和音素处理，不再强制展开成中文读音的字母串。日期、数字、电话使用打包的文本规则。原始台词保持不变。

## 体积、速度与缓存

0.4.1 把本地通知与制作音频分开：通知只选用已有缓存或随包预置音频，不调用模型。六种精选声音各有 done / subagent / error / ask 四种提示，总计 24 条、约 3 MB。缓存为空、模型释放、GUI 关闭时仍可直接播放。

优先播原台词缓存；未准备好时播「任务完成了。」「子任务完成了。」「出了点问题，请检查。」「需要你确认一下。」等对应状态提示，日志注明使用预置提示，不延后补播原句。六种精选声音使用同一声音的提示；其他声音暂用同性别晓禾 / 云舟，缓存齐备后恢复原设定。最终音量和静音仍生效，原配置、台词和绑定不改变。合成和试听准备阶段不占播放锁；已有声音正在播放时仍保持顺序，避免声音叠加。

量化 ONNX 权重 114,203,914 字节，103 种声音的风格向量 53,790,720 字节，连同词典和 CPU 运行库，完整资源约 225 MB。这是体积与人声表现之间的取舍，仍然只包含一个语音模型，不需要 Python、Node、显卡、安装器或本地服务。

现场合成仍比旧模型慢，只在试听、后台准备和导出时进行。启动和保存后会在后台预生成全部固定台词及宿主覆盖台词，移除旧版每轮 64 条上限；模型约 30～35 秒闲置后释放。不能把已有文件播放速度当成现场合成速度。通知路径验证会在移除模型与推理 DLL 的独立便携目录中运行，测量进程启动到提交 Windows 播放命令的时间；不把该边界称为扬声器实际出声延迟。

0.4.1 本机实测：缓存为空的四种状态，从启动播放进程到提交 Windows 播放命令为 66～76 毫秒；真实 hook 启动子进程路径为 104 毫秒；精确命中自定义台词缓存为 69 毫秒；同时进行真实模型试听时，HTTP 通知从发请求到提交播放为 180 毫秒。独立播放器工作集约 12～14 MiB，未加载推理库。验证包含中文及 emoji 路径、音量为 0、禁用状态、24 个声音状态组合和超过 64 条台词的缓存准备。详情见 `notification-latency-0.4.1.json`。

本机双线程、同一句约 4.7 秒通知的两轮实测：首次加载与合成为 13.8 秒、26.2 秒，模型已载入后的合成为 5.6～7.9 秒；运行内存峰值约 608～612 MiB，闲置释放后约 13 MiB。首次文件读取与机器负载会影响等待时间，缓存准备完成后重复检查为 0 毫秒。这些是当前机器的测量，不是所有设备的速度保证。

旧版资源保留供已打开的旧窗口继续运行，0.4.0 发布包只带新模型。旧发布 ZIP 仍保留。

## 配置升级

读取旧 `local:aishell3:` 声音时，按原性别转换到新模型的固定入口，并恢复原速、原调和温和后期参数。名称、ID、最终音量、启用状态、所有台词和宿主路由保留；在线和 Windows 系统音色不变。收藏保留旧 ID，同时补入对应的新模型声音；自存调音方案保留。载入只产生内存草稿，不重写配置；保存时有原文件备份和外部修改冲突保护。0.4.0 使用独立的音频缓存版本，不会播到旧模型文件。
